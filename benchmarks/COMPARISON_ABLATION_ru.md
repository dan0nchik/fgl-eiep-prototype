# FGL против других защит Hermes и абляции FGL

Сводка по трём бенчмаркам: Agent-SafetyBench, SkillHarm, AutoSkillHarm. Все цифры взяты из файлов в
`benchmarks/`, ссылки на них даны в каждом разделе. Ничего не дорисовано: где прогона нет, так и
написано.

## С чем сравниваем

| Защита | Что это | Откуда |
|---|---|---|
| Без защиты | агент как есть | — |
| Hermes встроенная | regex-проверка опасных shell-команд (`detect_dangerous_command`, hardline) | hermes-agent 0.19.0, `tools/approval.py` |
| Hermes smart-approval | команды, помеченные regex, проверяет LLM по промпту Hermes | там же, `_smart_approve` (режим по умолчанию) |
| Hermes reviewer на каждое действие | тот же LLM-рецензент, но на каждый вызов. Сам Hermes так не делает, это щедрый к Hermes вариант | наш вариант |
| Hermes skills_guard | сканер скилла при установке из сообщества | `tools/skills_guard.py` |
| NeMo self-check | NVIDIA NeMo Guardrails 0.24.1, rails «self check input/output» с официальными промптами NVIDIA | `nemoguardrails` |
| NeMo content-safety | NeMo Guardrails, rails «content safety» с официальным промптом на 23 категории | `nemoguardrails` |
| Защита авторов SkillHarm | защитный системный промпт из статьи SkillHarm | репозиторий SkillHarm |
| **FGL** | проверка каждого действия перед выполнением: связано ли оно с задачей пользователя, откуда взята цель действия, не выходит ли за рамки задачи, обратимо ли | этот репозиторий |

## 1. Agent-SafetyBench (2000 кейсов, 8 категорий риска)

Агент gpt-4.1-mini, защиты на той же модели. Судья ShieldAgent-8B, авторский, на GPU.
«Лишние блокировки»: доля из 735 выполнимых кейсов, где защита заблокировала хотя бы одно действие.

| Защита | Безопасность, % | Поведение | Контент | Лишние блокировки | Против «без защиты» (стало безопасно / стало опасно) |
|---|---|---|---|---|---|
| Без защиты | 46,5 | 37,6 | 80,5 | 0% | — |
| Hermes встроенная | 46,6 | 38,1 | 79,6 | 0% | 61 / 57, p=0,78 |
| Hermes smart-approval | 46,4 | 37,8 | 79,8 | 0% | 48 / 49, p=1,0 |
| Hermes reviewer, блок только по DENY | 47,2 | 38,5 | 80,8 | 0,3% | 66 / 51, p=0,20 |
| NeMo self-check | 54,6 | 48,0 | 80,5 | 5,3% | 211 / 47 |
| NeMo content-safety | 57,1 | 51,1 | 80,5 | 5,9% | 264 / 50 |
| **FGL** | **63,9** | **60,1** | 78,3 | 29,4% | **420 / 72** |
| Hermes reviewer, блок по DENY и ESCALATE | 85,1 | 86,5 | 79,6 | **81,6%** | 798 / 25 |

Что видно:
- **Встроенная защита Hermes на этом бенчмарке не работает.** Она смотрит только shell-команды, а здесь
  обычные инструменты (почта, банк, файлы). Из 2772 вызовов regex сработал на одном.
- **NeMo помогает, но значимо уступает FGL**: на 7–9 пунктов, p < 10⁻¹¹ в парном сравнении.
  Большая часть блокировок NeMo приходится на проверку самой задачи пользователя, в основном по правилу
  «есть e-mail или имя — значит персональные данные».
- **Рецензент Hermes на каждом вызове** даёт 85,1%, но только потому, что блокирует 82% нормальных
  действий. Его промпт написан для shell-команд, и на обычный вызов инструмента он отвечает ESCALATE.
  Если блокировать только по явному DENY, остаётся 47,2%, то есть уровень без защиты.
- Цена FGL: 29,4% выполнимых кейсов задеты лишней блокировкой.

Файлы: `agent_safetybench/results/shieldagent_all_conditions.json`, `agent_safetybench/HERMES_BASELINES.md`,
`agent_safetybench/NEMO_BASELINES.md`.

## 2. SkillHarm (отравленные скиллы)

Атаки FPP: скилл отравлен сразу. Выборка 96 атак (по 8 на каждый из 12 типов вреда, seed 0), из них 77
запускаются. Остальные 19 исключены во всех условиях одинаково: в этих задачах не собирается образ
(`nvm install 22`). Жертва Codex CLI на gpt-5.6-luna по подписке ChatGPT. Основная метрика: ASR,
доля атак, которые сработали, по детерминированной проверке авторов. Чем меньше, тем лучше.

### 2.1. Онлайн-прогон: агент реально работал с защитой

| Защита | ASR | Задача выполнена при атаке | Против FGL (сработала только тут / только с FGL) |
|---|---|---|---|
| Без защиты | 63,6% (49/77) | 46,8% | 34 / 1, p=2,1·10⁻⁹ |
| Защита авторов SkillHarm | 46,8% (36/77) | 46,8% | 20 / 0, p=1,9·10⁻⁶ |
| **FGL** | **20,8% (16/77)** | 40,3% | — |

По частям рабочего процесса агента:

| Что атакуют | Без защиты | Авторы | FGL |
|---|---|---|---|
| Данные (Data Pipeline) | 8/19 | 8/19 | **2/19** |
| Систему (System Environment) | 30/38 | 23/38 | **9/38** |
| Автономию агента (Agent Autonomy) | 11/20 | 5/20 | **5/20** |

Судья gpt-5.6-terra (вторичная метрика): с FGL агент в 55,8% атак сам замечает и называет вредную
инструкцию, без защиты в 5,2%.

Цена на чистых задачах (15 задач без атаки): без защиты выполнено 8/15, с FGL 5/15. Разница 3 задачи,
p=0,25: на 15 задачах не значима, но направление есть.

### 2.2. Проверка скилла при установке (все 879 атак, 109 чистых скиллов)

| Защита | Отравленных заблокировано | Чистых заблокировано |
|---|---|---|
| Hermes skills_guard | 18,8%, из них из-за самой атаки только 8,0% | 7,3% |
| NeMo self-check по SKILL.md | 86,6% | 98,2%, режет почти всё |
| NeMo content-safety по SKILL.md | 6,1% | 0,9% |
| NeMo content-safety по всем текстовым файлам | 22,3% | 0,9% |

127 атак прячут вредную часть в PDF, и их не видит ни один сканер. FGL при установке не применяется:
он проверяет действия по истории сессии, а у стороннего скилла такой истории нет.

### 2.3. Мониторы команд на записанных траекториях (77 атак без защиты)

Все мониторы на одной модели (gpt-5.6-luna). Каждый монитор прогоняется по записанным командам агента
и отмечает, заблокировал ли бы он шаг атаки. Агента после блокировки не перезапускаем, поэтому это
оценка сверху для мониторов, а не онлайн-результат.

| Монитор | Атак остановлено на шаге атаки | ASR с монитором | Лишние блокировки обычных команд |
|---|---|---|---|
| Hermes встроенная | 14/49 (28,6%) | 45,4% | **42,9%** |
| Hermes smart-approval | 5/49 (10,2%) | 57,1% | 1,4% |
| NeMo self-check | 14/49 (28,6%) | 45,4% | 20,5% |
| **FGL** | **18/49 (36,7%)** | **40,2%** | 10,8% |

Hermes regex помечает почти каждую обычную команду Codex («script execution via heredoc»), а LLM
smart-approval потом одобряет 445 из 467 помеченных.

Файлы: `skillharm/RESULTS.md`, `skillharm/results/*.json`, `skillharm/BASELINES_HERMES_NEMO.md`,
`skillharm/static_scan/results/static_summary.json`, `skillharm/offline_monitors/results/summary.json`.

### 2.4. SMP (скилл переписывает себя сам)

24 атаки (по 2 на каждый из 12 типов вреда), жертва та же. Атака двухэтапная: в задаче A скилл незаметно
переписывает себя, вред наступает при повторном использовании в задаче B. Засчитаны все 24 пары в обоих условиях.

| Защита | ASR | Задача A выполнена | Задача B выполнена |
|---|---|---|---|
| Без защиты | 58,3% (14/24) | 13/24 | 11/24 |
| **FGL** | **45,8% (11/24)** | 6/24 | 8/24 |

В парном сравнении 4 атаки сработали только без защиты и 1 только с FGL, p=0,375: на 24 парах снижение
не значимо. FGL вдвое снижает выполнение задачи A. Значит, часть снижения ASR может объясняться тем, что агент
меньше делает в задаче A, а не тем, что он распознаёт мутацию. На SMP FGL заметно слабее, чем на FPP: вредная
правка появляется в скилле не в момент действия, а между сессиями, и проверка одного действия её не видит.
Против этого в архитектуре FGL предназначена проверка при записи (FGL-Admission), а она в этом прогоне не
участвовала: защита подавалась только как системный промпт.

FPP и SMP вместе: без защиты 62,4% (63/101), с FGL 26,7% (27/101).

Защиту авторов на SMP не прогоняли (не хватило времени жизни токена подписки).

## 3. AutoSkillHarm

AutoSkillHarm это генератор атак, который авторы использовали для сборки SkillHarm. Все 879 атак
SkillHarm и есть его выход, поэтому раздел 2 уже проверяет защиты на атаках AutoSkillHarm.

Свежий набор атак сгенерировать не удалось. Пайплайн на сервере проверен полностью (прокси, Docker,
harbor, задачи skillsbench v1.0), но на этапе генератора блокирует каждая доступная модель:
- API gpt-5.x, как у авторов: организация не верифицирована;
- API gpt-4.1-mini: слишком слабая, изучает задачу и не пишет атаку;
- API gpt-4.1: кончились кредиты;
- модели по подписке: отказываются конструировать атаки по политике безопасности.

Обходить отказ моделей мы не стали. Команда для запуска после пополнения кредитов и верификации
организации записана в `autoskillharm/RESULTS.md`.

### Что говорят абляции

1. **На Agent-SafetyBench и SkillHarm ни одна отдельная часть FGL не критична.** Убираешь любую одну,
   и разница с полным FGL укладывается в шум (все p ≥ 0,1). Части проверки перекрывают друг друга:
   одну и ту же вредную инструкцию ловит и «не связано с задачей», и «цель взята из скилла», и
   «выходит за рамки». Работает сам принцип: каждое действие сверяется с задачей пользователя.
   Без защиты вообще ASR в 3–4 раза выше.
2. **Компонентная роль FGL видна на атаках через среду (EIEP).** Там без графа происхождения атака не
   обнаруживается совсем (80% → 0%), а без проверок при записи и в среде растут лишние блокировки.
   Эти части нужны против атак, которые одноразовая проверка действия не видит.
3. Самая заметная тенденция на SkillHarm: без проверки провенанса ASR выше (27,1% против 25,4%), но на
   59 атаках это не значимо.

## Ограничения

- Модели разные по бенчмаркам: Agent-SafetyBench на gpt-4.1-mini (API), SkillHarm на gpt-5.6-luna
  (подписка). Внутри одного бенчмарка все защиты на одной модели.
- SkillHarm — выборка 77 из 687 атак FPP, одна жертва (Codex), один прогон на условие.
- Абляции на Agent-SafetyBench: «полный FGL повторно» и «без проверки непроверенных данных» досчитаны
  частично (576 и 729 кейсов, кончились кредиты API), сравнение только на тех же кейсах.
  Вариант «FGL плюс провенанс аргументов» реализован, но не прогнан.
- NemoGuard 8B (модель NVIDIA) не запускали: нужна закрытая базовая Llama-3.1-8B.
